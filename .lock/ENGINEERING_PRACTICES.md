# Engineering practices

How changes are made in this repository. Everything below is read from the tree. "Not present" means it is absent from the repository; GitHub-side settings such as branch protection cannot be seen from the tree and are not claimed.

## 1. Run locally

```bash
make install && source .venv/bin/activate   # pip install --require-hashes -r requirements-dev.txt
cp .env.example .env                        # fill the placeholders; .env is gitignored
bash scripts/redis_setup.sh                 # starts Redis through Docker Compose
alembic upgrade head
make run-dev                                # API on port 8000, docs at /docs
make run-worker                             # automation worker; needs the automation settings
make check                                  # ruff, OpenAPI drift check, pytest
```

Required variable names (set in `.env`, never committed): `ENVIRONMENT`, `SERVICE_ROLE`, `AUTOMATION_ENABLED`, `DATABASE_URL`, `REDIS_URL`, `SECRET_KEY`, `ALGORITHM`, `JWT_ISSUER`, `JWT_AUDIENCE`, `GOOGLE_OAUTH_CLIENT_SECRETS`, `OAUTH_REDIRECT_URI`, `FRONTEND_OAUTH_CALLBACK_URI`, `GOOGLE_PROJECT_ID`, `GOOGLE_LOCATION`, `GOOGLE_MODEL`, `CORS_ALLOWED_ORIGINS`. Add `OAUTH_TOKEN_KEYRING_PATH` plus `OAUTH_TOKEN_ACTIVE_KEY_ID` (a pair; credential work fails closed without both). The worker also needs `AUTOMATION_OWNER_ID`, `PUBSUB_TOPIC`, `PUBSUB_SUBSCRIPTION`, `PUBSUB_PUSH_AUDIENCE`, `PUBSUB_PUSH_SERVICE_ACCOUNT_EMAIL`. Compose adds `POSTGRES_PASSWORD` and the `*_HOST_PATH` mount variables. The test suite imports settings, so these must be exported even for `pytest`.

## 2. CI pipeline

`.github/workflows/backend.yml`, "Backend checks". It runs on every pull request and on pushes to `main` and `backend/**`, with `contents: read` permission only.

| Job | What it checks |
| --- | --- |
| `quality` | Installs `requirements-dev.txt` with `--require-hashes`; `pip-compile --dry-run` on both `.in` files (inputs resolve; it does not diff the committed locks); `ruff check .`; `python scripts/generate_openapi.py --check`; `compileall`; `alembic upgrade head` then `alembic check` (model drift) against a PostgreSQL 16.6 service; `pytest -q`; `alembic heads` and `alembic history --verbose`; `docker compose config -q`. |
| `image` | `docker build --no-cache`, then asserts the container is non-root and holds no `.env`, `.git`, `tests`, or `*.json` file. Same as `make image-smoke`. |
| `secrets` | `gitleaks/gitleaks-action@v2` over full git history. |

Not present: coverage, type checking, `ruff format`, pre-commit hooks, dependency vulnerability scanning, Dependabot or Renovate, a PR template, CODEOWNERS. CI starts no Redis; tests use in-memory fakes.

## 3. Branching, PRs, commits

- **Commit directly to `main`** (owner decision, 2026-11-06): no topic branches and no pull requests. With no review gate, the definition of done below must pass locally before every commit. Pushing to the remote still happens only when the owner asks. History before this date shows `backend/...`, `docs/...` and `claude/...` branches and "Merge pull request" commits.
- Commits use lowercase Conventional Commits without scopes. The types actually used are `feat`, `fix`, `test`, `docs` and `refactor`. Subjects are imperative; bodies explain why. One early commit does not follow the style; do not copy it.
- Keep commits small and one-purpose, for example schema, then service, then route, then client types, then docs.

## 4. Definition of done

1. A failing test came first (see `TEST_STRATEGY.md`), and `make test` is green.
2. `make lint` is clean. Do not add entries to `[tool.ruff.lint.per-file-ignores]` in `pyproject.toml`; that list is a frozen legacy baseline.
3. Routes or public schemas changed: run `make contract`, commit `docs/openapi.json`, and update `frontend-client-types.ts` (`tests/unit/test_api_contract.py` guards both).
4. Schema changed: a migration is included with a working `downgrade()`, and `alembic check` passes.
5. New or changed settings are in `.env.example`, `docs/OPERATIONS.md`, and CI or Compose if required.
6. `README.md` and `docs/OPERATIONS.md` describe the new behavior.
7. No secrets, tokens, mail content, or personal data in code, tests, fixtures, or commit messages.

## 5. Database migrations

- File names are `<revision-id>_<snake_case_slug>.py` in `alembic/versions`, generated by Alembic (no custom `file_template` in `alembic.ini`). Write a real slug; the first file is the default `migration_message`, which is not a model to copy.
- Use expand/contract. `8f8a10d8c4f1` and `b4c6d8e0f2a4` are expand steps (add columns, keep a dual-read path, constrain after backfill). `OPERATIONS.md` and `.env.example` say the plaintext-token contraction has not run yet.
- Every migration defines `downgrade()`. `tests/integration/test_pending_action_migration.py` runs upgrade, a data check, and downgrade on a disposable database. A data-bearing change needs a similar test.
- Never downgrade shared data without an owner-approved, revision-specific plan and a restore test (`docs/OPERATIONS.md`, Rollback).
- Migrations run once, as a dedicated `migrate` role, before API or worker replicas; never inside API processes.

## 6. Configuration and secrets

- Settings are typed in `server/config.py`; unknown names fail startup (`extra="forbid"`). The checked-in `SECRET_KEY` placeholder and keys under 32 bytes are rejected. `combined` role is refused in production, and production needs TLS for PostgreSQL and `rediss://`.
- `.gitignore` excludes `.env`, `.env.*` (except `.env.example`) and every `*.json`, so `docs/openapi.json` needed force-adding; use `git add -f` only for intended JSON.
- Credential files, OAuth client files, service-account files and the token keyring are mounted read-only at runtime and never copied into the image (`.dockerignore` is default-deny).
- Examples and tests use `REPLACE_WITH_...` placeholders, `example.invalid` hosts, and reserved example domains.

## 7. Logging

- Use `logging.getLogger`; `server/logging_config.py` installs a redacting filter and correlation IDs. The filter is a safety net, not permission to log content.
- Log stable messages, error codes and IDs (action id, job id). Never log tokens, OAuth codes or state, authorization headers, mail bodies, subjects, recipient addresses, query text, tool arguments, LLM prompts, or provider error bodies.
- Tests assert this with sentinel strings (`tests/unit/test_input_logging.py`, `test_mark_as_read_does_not_log_provider_error_content`).

## 8. Dependencies

- `requirements.in` and `requirements-dev.in` hold exact `==` pins of direct dependencies. `requirements.txt` and `requirements-dev.txt` are pip-compile output (pip-tools 7.4.1) with hashes and are installed with `--require-hashes`. The Dockerfile installs only `requirements.txt` and pins the Python base image to a patch tag.
- To update: edit the `.in` file, run `pip-compile --generate-hashes --output-file=requirements.txt requirements.in`, then `pip-compile --allow-unsafe --generate-hashes --output-file=requirements-dev.txt requirements-dev.in`. Review the diff, commit `.in` and `.txt` together, and let CI confirm.
- Update the base image only in a reviewed PR together with the Dockerfile smoke check.

## 9. Security review checklist

Required in the PR description for any change touching auth, tokens, or external writes:

- [ ] Owner comes from the verified JWT principal, never a request parameter, and cross-owner access returns 404.
- [ ] JWT checks (algorithm, issuer, audience, `exp`) are unchanged or tested.
- [ ] Tokens stay encrypted (`server/security/oauth_credentials.py`), bound to user and account, and are never logged or returned.
- [ ] New external writes go through the ledger (section 10) with a server-issued `command_key`, canonical payload and hash.
- [ ] Non-idempotent writes use the single-dispatch path (`execute_google_request`), never the retrying helper.
- [ ] Ambiguous outcomes end in `reconciliation_required`, are audited, and are never auto-retried.
- [ ] Inbound mail and LLM output are treated as untrusted (bounded parsing, plain-text rendering, tool allowlist).
- [ ] New scopes, endpoints or settings are minimal, documented, and fail closed.
- [ ] gitleaks is clean and no real identifiers appear in the diff.

## 10. Every external write goes through the ledger

An agent-initiated send, reply, calendar event or task is stored as an immutable pending action (`server/services/pending_actions.py`), claimed under a row lock with a lease and attempt token, committed before dispatch, and audited. The documented exceptions are human API calls (`/mail/send`, deletion, mailbox mutations) and the interactive-only `create_draft` and `mark_as_read` tools (`docs/OPERATIONS.md`, `README.md`). A new exception needs a written reason in `docs/OPERATIONS.md` and security review. Connectors and providers planned in the roadmap must follow the same rule.
